# Justificación de mejoras

Versión 1.0. Comparación con el [prompt docente íntegro](prompt_inicial.md), sección 3 del [HTML](../fuentes/consigna/Tarea_wiki_IA_proyecto_BI.html).

| Cambio en la versión específica | Utilidad y evidencia |
| --- | --- |
| Sustituye campos genéricos por EMACRUZ, objetivos existentes, usuarios y decisión de revisión | Evita inventar un proyecto o confundir análisis con desarrollo web. El [README](../fuentes/originales/README.md) sigue siendo la base de los objetivos. |
| Identifica rutas, commits y manifiesto de integridad | Permite repetir el análisis de la misma versión y distingue la copia local antigua de GitHub. |
| Define ausencias semánticas, días binarios/textuales y cruce nocturno documentado | Evita que textos “No indicado” cuenten como información completa y que medianoche cause falsos errores. |
| Precisa población, numerador, duplicados, filtros y alcance semanal del KPI | Hace comprobable el cálculo sin atribuir cobertura o vigencia que no existen. |
| Ordena ingestas separadas, instantáneas y comparación por ID | Demuestra una iteración real; reconoce la dependencia del JSON respecto al Excel. |
| Exige lectura del índice, respuesta inicial, tres comprobaciones y versión revisada | Permite distinguir respuesta generada de afirmaciones contrastadas. |
| Añade lista de criterios técnicos, auditoría y reproducción sin dependencias | Convierte “mantener una wiki” en productos observables y verificables. |
| Separa aprobación humana, permiso institucional y control automático | Evita firmas ficticias y uso operativo prematuro. Mantiene el informe y publicación para otra tarea. |

El [prompt mejorado](prompt_mejorado.md) conserva las obligaciones de trazabilidad, privacidad y revisión del original. La especialización añade decisiones metodológicas académicas explícitas; no las presenta como normas de EMACRUZ. Una persona debe revisar su pertinencia antes de aplicar conclusiones a decisiones reales.
